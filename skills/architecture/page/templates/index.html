1. What it does

Notes keeps short text notes on your own computer. You type a command in the terminal (a window where you type instructions instead of clicking), and Notes saves or shows your notes.

2. The big picture

Click the diagram to open it full size and zoom.

The analogy we use everywhere: a library. You are a visitor. The program is the librarian. The notes folder is the shelf. You ask the librarian for something; the librarian walks to the shelf and brings it back.

4. Step by step: you ask to see a note

  1. You type notes show todo and press Enter. The terminal hands your words to the Notes program. Data: the words "show" and "todo".

    You walk up to the librarian's desk and ask for the book called "todo".

  2. The program checks the name is safe (arrow 1). It only allows letters, numbers, - and _, so nobody can trick it into opening a file outside the notes folder.

    The librarian makes sure you're asking for a book, not for the keys to the back office.

  3. The program reads the file notes/todo.md (arrow 2). A file is a named piece of saved text on the disk (the computer's long-term memory).

    The librarian takes the book off the shelf.

  4. The program prints the text in your terminal (arrow 3).

    The librarian hands you the book.

6. Glossary

ADR (Architecture Decision Record)
A short document that records one decision about how the app is built: the options, the choice, and why. Example: "store notes as files, not in a database".
CLI (Command Line Interface)
A program you use by typing commands instead of clicking buttons. Example: typing notes list.
File
A named piece of saved information on the disk. Example: todo.md.
Terminal
A window where you type instructions to the computer. Example: the Terminal app on a Mac.

7. Decisions

  • 0001: A command line program first, a website later.
  • 0002: Notes are plain files, not a database.
